# RANKING CONTRACT
# Excerpt — Multi-Objective Clip Ranking (Step 7)

> **Status**: COMPLETE
> The clip ranking subsystem has been deployed inside `@excerpt/clipping-core`. It strictly operates as a pure, zero-I/O function that absorbs configuration profiles to produce the canonical `RenderPlan`.

## 1. Zero-I/O Purity

The `ClipRankingEngine` sits entirely within the core package. It performs no database lookups, no AI inferences, and no external API requests. It accepts the `AuditableEvaluation[]` objects generated by Step 6, a versioned `RankingProfile`, and the total `requestedClips` integer.
Given identical inputs, it guarantees byte-identical outputs on every run.

## 2. Versioned Configuration Profiles

To prevent "magic numbers" hardcoded in the ranking logic, all weights have been externalized into `RankingProfile` definitions (e.g., `STANDARD_PROFILE`, `PODCAST_PROFILE`).
- **Data over Code**: Tuning the engine for gaming clips vs. interviews is now a data-driven config change, reviewable in a standard PR diff without altering the engine logic.
- **Dominance Ceiling Guardrail**: The `validateProfile()` hook runs mathematically on startup to ensure that *no single objective* (e.g., Hook Strength or Story) contributes more than **30%** of the overall composite score, ensuring true multi-objective balance.

## 3. Diversity Penalization

The ranking engine actively discourages clustering. The `applyDiversityPenalties` step cross-references the start times of all accepted clips. If two clips are temporally adjacent (e.g., within 30 seconds of one another), the lower-scoring candidate is mathematically penalized by the profile's `timeDiversityPenalty` coefficient.

## 4. Deterministic Tie-Breaks

To satisfy purity and determinism, identical composite scores (within `epsilon = 1e-6`) must be resolved uniformly without relying on random stability.
The tie-break rules are executed in sequence:
1. **Confidence Level**: The candidate with the higher `JudgeDecision.confidence` wins.
2. **Chronology**: If confidence is identical, the candidate occurring *earlier* in the timeline (`startMs`) wins.

## 5. Test Verification

4 explicit edge-cases in `ranking.test.ts` assert the engine's precision:
1. **Invariant 10**: Requesting 5 clips but providing only 2 viable candidates yields a `RenderPlan` with exactly 2 `renderJobs`. The engine refuses to pad the request.
2. **Deterministic Tie-Breaking**: Passing identical composite scores successfully triggers the secondary and tertiary tie-break clauses (Confidence, then Timestamp) to enforce ordering.
3. **Dominance Protection**: Injecting a mock profile where `hook = 0.8` mathematically fails the `validateProfile` hook, throwing a ceiling violation error.
4. **Data-Driven Execution**: Passing the identical set of candidates through two distinct profiles (`standard` vs `podcast`) yields two totally distinct ranking orders, proving behavior modifies purely via configuration.
