# Excerpt Access Control Architecture

This document outlines authentication, authorization, and data isolation mechanisms across Excerpt.

---

## 1. Authentication Layer

- **End Users**: Authenticate via Supabase Auth (OAuth2, magic links, or email/password). All API requests carry a signed JWT in the `Authorization: Bearer <token>` header.
- **Workers & Background Services**: Authenticate via dedicated `SUPABASE_SERVICE_ROLE_KEY` with elevated database privileges, restricted exclusively to internal worker containers.

---

## 2. Row-Level Security (RLS)

Database isolation is strictly enforced at the PostgreSQL engine level via Supabase RLS:

- Users can only `SELECT`, `INSERT`, `UPDATE`, or `DELETE` jobs and clips where `user_id = auth.uid()`.
- Public/unauthenticated access to clips and job tables is rejected by default (`RESTRICTIVE` policies).
- Internal workers operating via the service role bypass RLS to claim tasks across users.

---

## 3. Storage Access Control

- **Private Buckets**: Backblaze B2 buckets do not permit anonymous read or write requests.
- **Presigned URLs**: Users obtain time-limited presigned S3 URLs generated by `StorageService` for downloading clips or viewing previews.
- **Worker Egress**: Only worker instances have access to S3 write credentials.
